# 플레이그라운드 캔버스 편집기 1차 설계 (Playground Canvas Editor MVP)

- 날짜: 2026-07-31
- 대상 이슈: [#69](https://github.com/jojo3420/fontagit/issues/69) (방향 논의 #55 통합)
- 선행 문서: `docs/superpowers/specs/2026-07-18-playground-canvas-editor-design.md`. 이 문서가 1차 범위의 최신 정본이며, 7-18 문서와 어긋나는 항목은 이 문서를 따른다.
- 목표: `/playground`에서 폰트를 설치 없이 시험하게 해 폰트 탐색에서 다운로드로 이어지는 전환을 만든다.

## 착수 시점 사실 확인

- `/playground` 페이지는 존재하지 않는다. 7-18 문서가 전제한 플레이스헐더 컴포넌트도 현재 없다. 신규 구현이다.
- 선행 의존이던 `resolveFontPreview`는 구현 완료 상태다(`apps/web/lib/fontPreview.ts:24`). self-host는 `next/font` 패밀리, Tier A는 Google Fonts CSS2 주소, 그 외는 Pretendard 폴백을 돌려준다. 7-18 문서의 Slice 0은 불필요하다.
- 대상 폰트는 Tier A 140종이다(dev DB 실측: A 140, B 1,154). 분류는 전부 채워져 있다(고딕 98, 명조 20, 장식 14, 손글씨 8).
- 화면에 들어온 항목만 웹폰트를 주입하는 `LazyFontPreview`(`apps/web/components/LazyFontPreview.tsx:34`)를 폰트 목록에 재사용한다.
- 정적 내보내기(`output: "export"`)라 서버 라우트가 없다. 주소창 파라미터는 반드시 클라이언트에서 읽는다(서버 단계 접근은 이 프로젝트의 알려진 빌드 실패 원인).

## 1차 범위

포함: 텍스트 추가와 편집, 폰트 적용, 텍스트 속성 조절, 캔버스 크기 프리셋과 자유 크기, 되돌리기와 다시하기, PNG 내보내기, 라이선스 고지, 폰트 상세로 가는 전환 링크, 좁은 화면 안내.

제외(2차 이슈로 분리): 도형 그리기, 이미지 업로드, PDF 내보내기, 작업 저장과 복원, 모바일 편집, 시작 템플릿.

## 결정 사항

| 항목 | 결정 |
| --- | --- |
| 캔버스 크기 | 프리셋 3종(1280x720, 1080x1080, 2560x1440) + 자유 크기(한 변 최대 4096), 줌 25~200% |
| 화면 배치 | 3분할. 좌측 폰트 목록, 가운데 캔버스, 우측 속성 패널 |
| 폰트 목록 | 분류 칩(전체/고딕/명조/손글씨/장식) + 검색 + 미리보기. 미리보기 문구는 선택된 텍스트 내용, 선택이 없으면 기본 문구 |
| 첫 화면 | 빈 캔버스 + 안내 문구 |
| 텍스트 생성 | 상단 "텍스트 추가" 버튼만 |
| 선택 없이 폰트 클릭 | 다음에 추가할 텍스트의 기본 폰트로 기억하고 목록에 선택 표시 |
| 속성 범위 | 크기, 굵기, 색, 정렬, 자간, 행간, 불투명도 |
| 되돌리기 | 1차 포함. JSON 스냅샷 스택, 깊이 30, Cmd/Ctrl+Z와 Shift 조합 |
| 작업 보존 | 저장하지 않음. 편집 내용이 있을 때 이탈하면 경고만 |
| 진입 경로 | 헤더 메뉴에 추가 + 폰트 상세의 "이 폰트로 만들어보기" 버튼(`?font=슬러그` 전달) |
| 좁은 화면 | 1024px 미만은 편집기 대신 안내 화면 |
| 내보내기 | PNG만. 배수는 자동 결정, 결과 크기를 문구로 안내 |
| 라이선스 고지 | 내보내기 직전에 사용 폰트 목록과 상세 링크를 함께 표시 |
| 크기 변경 시 | 가로세로 변화율 중 작은 쪽 기준으로 모든 객체 위치와 크기를 함께 조정 |
| 측정 이벤트 | 폰트 적용, 폰트 상세 이동, PNG 내보내기 3개 |
| 캔버스 라이브러리 | Fabric 7.4.0 |

### 라이브러리 선택 근거

Fabric은 캔버스 위 더블클릭 인라인 텍스트 편집, 선택 손잡이, PNG 출력을 모두 내장한다. Konva(10.3.0)는 더 가볍지만 인라인 텍스트 편집이 없어 입력창을 겹쳐 띄우고 위치와 줄바꿈을 직접 맞춰야 하며, 한글 조합 입력에서 특히 취약하다. 대신 Fabric은 배포 패키지 원본이 22MB로 Konva 1.5MB보다 크다(`npm view dist.unpackedSize`). 여러 빌드 형식과 타입 정의를 포함한 수치라 실제 전송량과는 다르므로, `/playground` 진입 시에만 불러오도록 분리하고 구현 초기에 빌드 결과로 전송량을 실측한다.

## 구조

```
app/playground/page.tsx          빌드 시점 폰트 조회, 메타데이터
components/playground/
  PlaygroundEditor.tsx           화면 폭 판단, 전체 배치, Fabric 지연 로드
  CanvasStage.tsx                캔버스 생성-표시-정리
  EditorToolbar.tsx              텍스트 추가, 되돌리기, 삭제-복제, 순서, 크기 선택
  FontPickerPanel.tsx            분류 칩, 검색, 폰트 목록
  PropertiesPanel.tsx            선택 객체 속성
  ExportButton.tsx               저장 실행
  LicenseNoticeDialog.tsx        저장 직전 라이선스 고지
  FontFunnelCta.tsx              폰트 상세 링크
  NarrowScreenNotice.tsx         1024px 미만 안내
hooks/
  useFabricCanvas.ts             캔버스 수명주기와 선택 이벤트 구독
  useUndoStack.ts                스냅샷 스택 상태
lib/playground/
  canvasPresets.ts               프리셋 정의와 자유 크기 검증
  fontLoading.ts                 스타일시트 주입, 순번, 타임아웃
  rescaleObjects.ts              크기 변경 시 재배치 계산
  exportPng.ts                   배수 계산과 파일명 생성
  snapshot.ts                    스냅샷 직렬화와 스택 규칙
```

상태의 정본은 Fabric 캔버스 하나다. 패널들은 선택 변경 이벤트를 구독해 표시만 갱신하고 같은 값을 따로 저장하지 않는다. `lib/playground/` 아래는 전부 순수 함수로 두어 캔버스 없이 테스트한다.

## 동작 규칙

**폰트 적용**: 스타일시트를 한 번만 주입하고 브라우저가 실제 로딩을 마칠 때까지 기다린 뒤 적용한다. 로딩 전 적용은 글자 폭 계산을 어긋나게 한다. 요청마다 순번을 부여해 연타 시 마지막 선택만 반영하고 이전 응답은 버린다. 5초를 넘기거나 실패하면 기존 폰트를 유지하고 안내를 띄운다.

**되돌리기**: 캔버스 전체 JSON 스냅샷을 최대 30장 유지한다. 찍는 시점은 객체 추가, 삭제, 이동과 크기조절 종료, 속성 변경 확정이다. 슬라이더 드래그 중에는 찍지 않는다.

**캔버스 크기 변경**: 가로와 세로 변화율 중 작은 쪽을 배율로 삼아 모든 객체의 위치, 크기, 글자 크기를 함께 조정한다. 한 축만 기준으로 하면 다른 축에서 객체가 밖으로 나간다.

**내보내기**: 캔버스 크기와 총 픽셀 상한(1600만)에 맞춰 배수를 자동 결정한다. 파일명은 `fontagit-{가로}x{세로}-{날짜}.png`.

**전환 링크**: 텍스트 객체를 하나만 선택했을 때만 그 폰트의 상세 링크를 노출한다. 여러 개를 선택했거나 선택이 없으면 숨긴다.

**상태 처리**: 텍스트가 없으면 캔버스에 안내 문구를 두고 폰트 목록은 계속 쓸 수 있다. 검색 결과가 없으면 없다고 알린다. 폰트 목록 자체는 빌드 시점 데이터라 실행 중 로딩과 실패 상태가 없다.

## 검증 계획

단위 테스트 대상은 `lib/playground/`의 순수 함수 4종이다. 폰트 로딩의 순번과 타임아웃 처리, 스냅샷 스택의 깊이 제한과 되돌리기 순서, 크기 변경 재배치 계산, 내보내기 배수와 파일명 생성. Fabric에 의존하는 컴포넌트는 목으로 대체한다.

브라우저 테스트는 두 개만 만든다. 텍스트 추가에서 폰트 적용을 거쳐 PNG 저장까지 이어지는 흐름, 폰트 적용 후 상세 페이지로 이동하는 전환 흐름. 1024px 미만 안내는 창 크기를 줄여 확인한다.

## 위험과 대응

- 웹폰트 로딩 지연으로 글자 폭이 어긋날 수 있다. 로딩 완료 후 적용과 타임아웃 폴백으로 막는다.
- 큰 캔버스에서 내보내기가 메모리 한계로 실패할 수 있다. 총 픽셀 상한으로 배수를 눌러 예방하고, 실패 시 안내한다.
- Fabric 번들이 다른 페이지 속도를 떨어뜨릴 수 있다. 지연 로드로 분리하고 구현 초기에 빌드 결과를 실측한다.
- 무료 폰트라도 임베드 허용 범위는 폰트마다 다르다. 목록과 저장 직전 두 지점에서 상세 링크로 확인 경로를 남긴다.
