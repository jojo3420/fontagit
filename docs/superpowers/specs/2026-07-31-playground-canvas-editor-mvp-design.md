# 플레이그라운드 캔버스 편집기 1차 설계 (Playground Canvas Editor MVP)

- 날짜: 2026-07-31
- 대상 이슈: [#69](https://github.com/jojo3420/fontagit/issues/69) (방향 논의 #55 통합)
- 선행 문서: `docs/superpowers/specs/2026-07-18-playground-canvas-editor-design.md`. 이 문서가 1차 범위의 최신 정본이며, 7-18 문서와 어긋나는 항목은 이 문서를 따른다.
- 목표: `/playground`에서 폰트를 설치 없이 시험하게 해 폰트 탐색에서 다운로드로 이어지는 전환을 만든다.

## 착수 시점 사실 확인

- `/playground` 페이지는 존재하지 않는다. 7-18 문서가 전제한 플레이스홀더 컴포넌트도 현재 없다. 신규 구현이다.
- 선행 의존이던 `resolveFontPreview`는 구현 완료 상태다(`apps/web/lib/fontPreview.ts:24`). self-host는 `next/font` 패밀리, Tier A는 Google Fonts CSS2 주소, 그 외는 Pretendard 폴백을 돌려준다. 7-18 문서의 Slice 0은 불필요하다.
- 대상 폰트는 Tier A 140종이다(dev DB 실측: A 140, B 1,154). 분류는 전부 채워져 있다(고딕 98, 명조 20, 장식 14, 손글씨 8).
- 화면에 들어온 항목만 웹폰트를 주입하는 `LazyFontPreview`(`apps/web/components/LazyFontPreview.tsx:34`)를 폰트 목록에 재사용한다.
- 정적 내보내기(`output: "export"`)라 서버 라우트가 없다. 주소창 파라미터는 반드시 클라이언트에서 읽는다(서버 단계 접근은 이 프로젝트의 알려진 빌드 실패 원인).
- `useSearchParams`를 쓰는 컴포넌트는 반드시 `<Suspense>` 경계 안에 둔다. 감싸지 않으면 정적 내보내기 빌드가 깨진다. 이 프로젝트의 기존 페이지들과 같은 방식이다(`apps/web/app/fonts/page.tsx:17`, `apps/web/app/search/page.tsx:136`).
- 미리보기 유틸 `resolveFontPreview`는 목록용이라 굵기를 400과 700만 불러온다(`apps/web/lib/fontPreview.ts:35`). 편집기는 굵기를 자유 선택하므로 이 함수를 그대로 쓸 수 없고, 굵기를 지정해 주소를 만드는 경로가 따로 필요하다.

## 1차 범위

포함: 텍스트 추가와 편집, 폰트 적용, 텍스트 속성 조절, 캔버스 크기 프리셋과 자유 크기, 되돌리기와 다시하기, PNG 내보내기, 라이선스 고지, 폰트 상세로 가는 전환 링크, 좁은 화면 안내.

제외(2차 이슈로 분리): 도형 그리기, 이미지 업로드, PDF 내보내기, 작업 저장과 복원, 모바일 편집, 시작 템플릿.

### 7-18 설계 대비 변경

선행 문서와 어긋나는 지점만 추린다. 표에 없는 항목은 7-18 문서를 그대로 따른다.

| 항목 | 7-18 문서 | 이 문서 | 사유 |
| --- | --- | --- | --- |
| Slice 0 (`resolveFontPreview` 선행 구현) | 착수 조건 | 삭제 | 이미 구현 완료(`apps/web/lib/fontPreview.ts:24`) |
| 도형 그리기, 이미지 업로드 | 1차 포함 | 2차로 분리 | 폰트를 시험한다는 목표에 직접 기여하지 않음 |
| PDF 내보내기 | 1차 포함 | 2차로 분리 | PNG만으로 전환 목표 검증 가능 |
| Fabric 버전 | v6 기준 서술 | 7.4.0 | 채택 버전이 다르므로 API 이름은 실험으로 재확인 |
| `ExportMenu` | 단일 컴포넌트 | `ExportButton` + `LicenseNoticeDialog` | 저장 실행과 라이선스 고지를 각각 하나의 책임으로 분리 |
| `FontPicker` | 이름 그대로 | `FontPickerPanel` | 분류 칩과 검색을 포함한 패널 단위임을 이름에 반영 |

## 결정 사항

| 항목 | 결정 |
| --- | --- |
| 캔버스 크기 | 프리셋 3종(1280x720, 1080x1080, 2560x1440) + 자유 크기(한 변 320~3840, 그리고 가로x세로가 1200만 픽셀 이하), 줌 25~200% |
| 화면 배치 | 3분할. 좌측 폰트 목록, 가운데 캔버스, 우측 속성 패널 |
| 폰트 목록 | 분류 칩(전체/고딕/명조/손글씨/장식) + 검색 + 미리보기. 미리보기 문구는 선택된 텍스트 내용, 선택이 없으면 기존 예문 유틸 `pickPhrase`(`apps/web/lib/specimenPhrases.ts:77`)가 돌려주는 문구 |
| 첫 화면 | 빈 캔버스 + 안내 문구. `?font=`로 들어왔으면 그 폰트를 기본 폰트로 잡고 안내 문구에 폰트 이름을 넣는다(텍스트를 자동으로 만들지는 않는다) |
| 텍스트 생성 | 상단 "텍스트 추가" 버튼만 |
| 선택 없이 폰트 클릭 | 다음에 추가할 텍스트의 기본 폰트로 기억하고 목록에 선택 표시 |
| 속성 범위 | 크기, 굵기, 색, 정렬, 자간, 행간, 불투명도. 굵기 선택지는 그 폰트의 `availableWeights`에 있는 값만 노출 |
| 되돌리기 | 1차 포함. JSON 스냅샷 스택, 깊이 30, Cmd/Ctrl+Z와 Shift 조합. 텍스트 편집 중이거나 입력창에 초점이 있으면 캔버스 단축키는 동작하지 않음 |
| 작업 보존 | 저장하지 않음. 편집 내용이 있을 때 이탈하면 경고만 |
| 진입 경로 | 헤더 메뉴에 추가 + 폰트 상세의 "이 폰트로 만들어보기" 버튼. 버튼은 편집기가 지원하는 폰트에서만 노출하고 `?font=슬러그`를 넘김 |
| 좁은 화면 | 1024px 미만은 편집기 대신 안내 화면 |
| 내보내기 | PNG만. 배경은 흰색 불투명, 배수는 자동 결정, 결과 크기를 문구로 안내 |
| 라이선스 고지 | 내보내기 직전에 사용 폰트 목록과 상세 링크를 함께 표시. 링크는 모두 새 탭 |
| 크기 변경 시 | 가로세로 변화율 중 작은 쪽 하나를 배율로 삼아 모든 객체를 조정. 배율은 한 곳에만 곱한다 |
| 측정 이벤트 | 폰트 적용, 폰트 상세 이동, PNG 내보내기 3개 |
| 캔버스 라이브러리 | Fabric 7.4.0 |
| 텍스트 객체 | 폭이 고정되고 자동 줄바꿈되는 종류(v6 기준 `Textbox`)를 쓴다. 7.4.0에서의 실제 이름은 구현 첫 단계 실험에서 확인 |

### 기본값

구현자가 임의로 정하지 않도록 초기값과 허용 범위를 못 박는다.

| 대상 | 값 |
| --- | --- |
| 최초 캔버스 | 1280x720, 줌은 화면에 맞춰 자동 |
| 최초 기본 폰트 | 목록 첫 항목이 아니라 Pretendard 계열 self-host 폰트 하나를 고정 지정 |
| 새 텍스트 내용 | "여기에 글자를 입력하세요" |
| 새 텍스트 위치 | 캔버스 가운데. 겹치지 않게 추가할 때마다 오른쪽 아래로 20px씩 밀어 놓는다 |
| 새 텍스트 크기 | `fontSize` 48, 폭은 캔버스 가로의 60% |
| 글자 크기 | 8~400, 정수 |
| 자간 | -0.1~0.5em, 소수 둘째 자리까지 |
| 행간 | 0.8~3.0배, 소수 첫째 자리까지 |
| 불투명도 | 0~100%, 정수 |
| 색 | 16진수 색상값. 기본 검정 |

범위를 벗어난 입력은 가장 가까운 경계값으로 잘라 넣고, 입력창에도 잘린 값을 되돌려 보여준다.

### 라이브러리 선택 근거

Fabric은 캔버스 위 더블클릭 인라인 텍스트 편집, 선택 손잡이, PNG 출력을 모두 내장한다. Konva(10.3.0)는 더 가볍지만 인라인 텍스트 편집이 없어 입력창을 겹쳐 띄우고 위치와 줄바꿈을 직접 맞춰야 하며, 한글 조합 입력에서 특히 취약하다. 대신 Fabric은 배포 패키지 원본이 22MB로 Konva 1.5MB보다 크다(`npm view dist.unpackedSize`). 여러 빌드 형식과 타입 정의를 포함한 수치라 실제 전송량과는 다르므로, `/playground` 진입 시에만 불러오도록 분리하고 구현 초기에 빌드 결과로 전송량을 실측한다.

캔버스 문서(객체와 그 속성)의 정본은 Fabric 캔버스 하나다. 패널들은 선택 변경 이벤트를 구독해 표시만 갱신하고 같은 값을 따로 저장하지 않는다. 검색어, 줌 배율, 다음에 추가할 기본 폰트처럼 캔버스에 담기지 않는 값은 각 컴포넌트가 따로 들고 있어도 된다.

`lib/playground/` 6개 파일 중 `fontLoading.ts`만 부수 효과를 갖는다. 나머지 5개는 순수 함수로 두어 캔버스 없이 테스트하고, `fontLoading.ts`는 브라우저 테스트에서 확인한다.

### 폰트 메타데이터 계약

빌드 시점에 편집기로 넘기는 폰트 항목은 아래 필드만 쓴다. 전부 기존 `Font` 타입에 있으므로 새 컬럼은 필요 없다(`apps/web/types/font.ts:41`).

| 필드 | 용도 |
| --- | --- |
| `slug` | `?font=` 값 검증 기준, 상세 링크 주소 |
| `nameKo`, `nameEn` | 목록 표시, Google Fonts 조회 이름 |
| `fontKey` | self-host 폰트 판별 |
| `sourceTier` | Tier A 판별 |
| `category` | 분류 칩 |
| `availableWeights` | 굵기 선택지 (단일 굵기 폰트는 `[400]`) |
| `license` | 저장 직전 라이선스 고지 |

지원 대상은 `fontKey`가 있는 self-host 폰트와 `sourceTier`가 A인 폰트다. 나머지는 화면에 Pretendard 폴백으로 뜨는 탓에 폰트를 시험한다는 목적이 성립하지 않으므로, 폰트 목록과 상세의 진입 버튼 양쪽에서 뺀다.

`?font=` 값이 이 목록에 없으면 조용히 폴백하지 않고 "지원하지 않는 폰트" 안내를 띄운 뒤 빈 캔버스로 시작한다. 잘못된 폰트가 적용된 채로 편집을 이어가면 사용자가 결과물을 오해한다.

## 동작 규칙

**폰트 적용**: 폰트 이름과 굵기 조합마다 스타일시트를 한 번만 주입하고, 그 조합의 로딩이 실제로 끝날 때까지 기다린 뒤 적용한다. 로딩 전 적용은 글자 폭 계산을 어긋나게 한다. 굵기를 바꿀 때도 같은 절차를 밟는다. 이미 주입한 조합은 다시 주입하지 않는다.

요청마다 순번을 부여해 연타 시 마지막 선택만 반영하고 이전 응답은 버린다. 순번만으로는 부족해서, 응답이 도착했을 때 다음 세 가지를 모두 확인한 뒤에만 적용한다.

- 대상 객체가 아직 캔버스에 있는가 (삭제됐으면 버린다)
- 그 객체의 폰트가 요청 당시와 같은가 (되돌리기로 바뀌었으면 버린다)
- 순번이 최신인가

5초를 넘기거나 실패하면 기존 폰트를 유지하고 안내를 띄운다.

**목록 미리보기와 캔버스의 폰트 주입은 같은 캐시를 본다**: 이미 주입한 조합을 한 곳에서 관리해, 목록에서 이미 불러온 폰트를 캔버스가 다시 요청하지 않게 한다.

**되돌리기**: 캔버스 전체 JSON 스냅샷을 최대 30장 유지한다. 편집기가 열릴 때 최초 상태를 먼저 한 장 찍어 첫 작업도 되돌릴 수 있게 한다.

찍는 시점은 다음과 같다.

- 객체 추가, 삭제, 복제, 순서 변경
- 이동과 크기조절 종료
- 속성 변경 확정 (슬라이더 드래그 중에는 찍지 않는다)
- 글자 내용 편집 종료
- 폰트 적용 완료 (로딩이 끝나 실제로 반영된 뒤)
- 캔버스 크기 변경 완료

되돌린 뒤 새로 편집하면 그 지점보다 뒤에 있던 다시하기 기록은 버린다. 스냅샷을 복원하는 동안 발생하는 캔버스 이벤트는 기록하지 않는다. 그러지 않으면 복원 자체가 새 기록으로 쌓여 되돌리기가 제자리를 맴돈다.

**캔버스 크기 변경**: 가로와 세로 변화율 중 작은 쪽을 배율로 삼는다. 한 축만 기준으로 하면 다른 축에서 객체가 밖으로 나간다.

배율은 위치와 `scaleX`/`scaleY`에만 곱하고 `fontSize`는 건드리지 않는다. Fabric에서 글자의 화면 크기는 `fontSize`와 `scale`의 곱이라, 둘 다 곱하면 배율이 제곱으로 적용돼 글자가 터무니없이 커지거나 작아진다. 예를 들어 1280x720에서 2560x1440으로 갈 때 배율은 2이고, `fontSize` 40에 `scaleX` 1이던 글자는 `fontSize` 40에 `scaleX` 2가 되어 화면상 80으로 보인다.

배율을 적용하고 남는 여백은 객체 무리 전체를 캔버스 가운데에 놓아 처리한다.

**내보내기**: 캔버스 크기와 총 픽셀 상한(1600만)에 맞춰 배수를 자동 결정한다. 캔버스 자체는 1200만 픽셀 이하이므로 배수 1은 항상 가능하고, 여유가 있으면 2배까지 올린다. 최종 픽셀 수는 `가로 x 세로 x 배수 x 배수`로 계산해 상한과 비교한다.

출력 규칙은 다음과 같다.

- 배경은 흰색 불투명으로 채운다. 투명 배경은 흰 바탕 서비스에 붙였을 때 글자만 떠 보이는 사고가 잦다.
- 화면 줌 배율은 출력에 반영하지 않는다. 줌은 보기 편하려고 쓰는 값이지 문서 크기가 아니다.
- 선택 테두리와 크기 손잡이는 출력 전에 선택을 해제해 지운다.
- 저장 직전에 캔버스에 쓰인 모든 폰트와 굵기 조합의 로딩이 끝났는지 다시 확인한다.
- 저장 결과 크기를 문구로 알린다(예: "2560 x 1440 픽셀로 저장했습니다").

파일명은 `fontagit-{가로}x{세로}-{날짜}.png`.

**자유 크기 검증**: 한 변은 320 이상 3840 이하, 가로x세로는 1200만 픽셀 이하여야 한다. 숫자가 아니거나 범위를 벗어나면 적용하지 않고 그 자리에서 이유를 알린다. 3840x3840 같은 값은 한 변 조건은 통과하지만 픽셀 조건에서 걸린다.

**단축키**: 되돌리기는 Cmd/Ctrl+Z, 다시하기는 Cmd/Ctrl+Shift+Z와 Ctrl+Y 둘 다 받는다. 선택 객체 삭제는 Delete와 Backspace다.

다음 상황에서는 캔버스 단축키를 전부 막는다. 막지 않으면 글자를 지우려던 Backspace가 객체를 통째로 지우고, 되돌리기가 편집 중인 글자 대신 캔버스를 되돌린다.

- 텍스트 객체를 편집 중일 때 (Fabric의 `isEditing`이 참)
- 속성 패널의 숫자 입력창이나 검색창에 초점이 있을 때

**전환 링크**: 텍스트 객체를 하나만 선택했을 때만 그 폰트의 상세 링크를 노출한다. 여러 개를 선택했거나 선택이 없으면 숨긴다.

편집기 안의 모든 외부 이동 링크는 새 탭으로 연다. 같은 탭에서 이동하면 편집 내용이 있을 때 이탈 경고가 뜨는데, 폰트 상세로 보내는 것이 이 기능의 목표라 경고가 목표를 방해한다. 새 탭이면 편집물을 지키면서 상세도 볼 수 있다.

**캔버스 밖으로 나간 객체**: 객체를 캔버스 밖으로 완전히 끌고 나가지 못하게 막는다. 어느 방향으로든 객체의 일부(최소 20px)는 캔버스 안에 남도록 이동 좌표를 제한한다. 저장 기능이 없는 1차 범위에서 객체를 잃어버리면 되찾을 방법이 되돌리기밖에 없다.

**측정 이벤트**: 기록 시점은 성공한 뒤로 못 박는다.

- 폰트 적용: 로딩이 끝나 캔버스에 실제로 반영된 뒤
- 폰트 상세 이동: 링크를 누른 시점
- PNG 내보내기: 파일 생성에 성공한 뒤

보내는 값은 폰트 슬러그, 캔버스 크기, 내보내기 배수 같은 식별자와 수치뿐이다. 사용자가 캔버스에 입력한 문구는 절대 보내지 않는다. 개인적인 내용이 들어갈 수 있고, 측정에 필요하지도 않다.

**좁은 화면 전환**: 창을 줄여 1024px 아래로 내려가면 편집기를 화면에서 내리되 캔버스 상태는 메모리에 그대로 둔다. 다시 넓히면 작업하던 내용이 그대로 보인다. 페이지를 새로 열면 사라지는 것은 저장하지 않는다는 결정 그대로다.

**상태 처리**: 텍스트가 없으면 캔버스에 안내 문구를 두고 폰트 목록은 계속 쓸 수 있다. 검색 결과가 없으면 없다고 알린다. 폰트 목록 자체는 빌드 시점 데이터라 실행 중 로딩과 실패 상태가 없다.

## 검증 계획

### 구현 첫 단계 실험

7-18 문서의 API 이름은 Fabric v6 기준인데 채택 버전은 7.4.0이다. 문서만 읽어서는 실제 동작이 확인되지 않으므로, 다른 코드를 쓰기 전에 작은 시험 페이지를 만들어 아래 다섯 가지를 눈으로 확인한다. 여기서 어긋나는 항목이 나오면 이 설계를 먼저 고친다.

1. 폭 고정 자동 줄바꿈 텍스트 객체의 실제 클래스 이름과 인라인 편집 동작
2. 한글 조합 입력. 자모가 합쳐지는 도중에 글자가 깨지거나 커서가 튀지 않는지
3. 캔버스 JSON 직렬화와 복원. 폰트 이름 같은 값이 왕복 후에도 남아 있는지
4. React에서 캔버스가 두 번 초기화될 때(개발 모드 이중 실행) 정리가 제대로 되는지
5. 배수를 넣은 PNG 출력. 배경색과 선택 테두리가 결과에 어떻게 들어가는지

단위 테스트 대상은 `lib/playground/`의 순수 함수 5종이다.

- `canvasPresets`: 자유 크기 검증. 한 변 경계값(319/320/3840/3841)과 픽셀 상한 경계(3840x3125 통과, 3840x3126 거부)
- `fontUrl`: 굵기를 포함한 주소 조립, 지원 폰트 판별. `sourceTier`가 A도 아니고 `fontKey`도 없는 폰트를 걸러내는지
- `snapshot`: 스택 깊이 제한, 되돌리기 순서, 되돌린 뒤 새 편집 시 다시하기 기록 삭제
- `rescaleObjects`: 크기 변경 배율 계산. 배율이 `fontSize`에 곱해지지 않는지, 가운데 정렬 여백 계산
- `exportPng`: 배수 계산과 파일명 생성. 배수 2가 상한을 넘으면 1로 내려가는지

`fontLoading`은 문서에 스타일시트를 넣는 부수 효과 모듈이라 단위 테스트 대신 브라우저 테스트에서 확인한다. Fabric에 의존하는 컴포넌트는 목으로 대체한다.

브라우저 테스트는 두 개만 만든다. 텍스트 추가에서 폰트 적용을 거쳐 PNG 저장까지 이어지는 흐름, 폰트 적용 후 상세 페이지로 이동하는 전환 흐름. 1024px 미만 안내는 창 크기를 줄여 확인한다.

첫 흐름에는 한글을 실제로 입력하는 단계와 저장된 PNG의 픽셀 크기를 확인하는 단계를 넣는다. 한글 조합 입력과 실제 이미지 출력은 Fabric 목으로는 잡히지 않는 영역이다.

## 완료 조건

아래를 모두 만족해야 1차를 끝난 것으로 본다.

- 1차 범위의 기능이 전부 동작한다
- 단위 테스트 5종과 브라우저 테스트 2종이 통과한다
- 지원 브라우저에서 확인한다: Chrome, Safari, Edge 각 최신 버전과 하나 이전 버전. Safari는 한글 입력과 PNG 저장을 반드시 포함한다
- `/playground` 진입 시 새로 받는 자바스크립트가 500KB(압축 후)를 넘지 않는다. 넘으면 지연 로드 범위를 다시 나눈다
- 다른 페이지의 번들 크기가 이번 작업 전보다 늘지 않는다
- 키보드만으로 텍스트 추가, 폰트 선택, 속성 변경, 내보내기까지 도달할 수 있다
- 라이선스 고지 대화상자가 열리면 초점이 대화상자 안으로 들어가고, 닫으면 열기 전 위치로 돌아온다. Esc로 닫힌다

## 위험과 대응

- 웹폰트 로딩 지연으로 글자 폭이 어긋날 수 있다. 로딩 완료 후 적용과 타임아웃 폴백으로 막는다.
- 큰 캔버스에서 내보내기가 메모리 한계로 실패할 수 있다. 총 픽셀 상한으로 배수를 눌러 예방하고, 실패 시 안내한다.
- Fabric 번들이 다른 페이지 속도를 떨어뜨릴 수 있다. 지연 로드로 분리하고 구현 초기에 빌드 결과를 실측한다.
- 7-18 문서의 API 이름은 Fabric v6 기준인데 채택 버전은 7.4.0이다. 공식 문서 확인만으로는 부족해 구현 첫 단계 실험(검증 계획 참고)에서 실제로 돌려본다. 확인 전까지는 v6 기준 서술을 그대로 믿지 않는다.
- 무료 폰트라도 임베드 허용 범위는 폰트마다 다르다. 목록과 저장 직전 두 지점에서 상세 링크로 확인 경로를 남긴다.
