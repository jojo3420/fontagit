# 플레이그라운드 캔버스 편집기 설계 v2 (Playground Canvas Editor)

- 날짜: 2026-07-30
- 이슈: [#69](https://github.com/jojo3420/fontagit/issues/69) (방향 논의 #55 통합)
- 상태: 브레인스토밍 확정, 듀얼 리뷰 반영 완료, 구현 계획 대기
- 리뷰: 2026-07-30 Codex(gpt-5.5 xhigh) + agy(gemini-3.5-flash-high) 듀얼 리뷰, 결과 `docs/review/review-result-dual-20260730-205443.md`. Must 9건 Should 7건 반영
- 선행 문서: `docs/superpowers/specs/2026-07-18-playground-canvas-editor-design.md` (이 문서가 대체한다)

## 목적과 성공 기준

폰트를 설치하지 않고도 무료 서체 여러 개를 조합해 레이아웃과 배치를 실험하는 작업대를 제공한다. 인디자인이나 피그마에서 하던 타이포그래피 실험을 브라우저에서 가볍게 재현하는 것이 목표다.

- 1순위: 실험 경험. 지표는 편집 체류와 한 작업에서 적용한 폰트 수.
- 2순위(보조): 폰트 상세 이동 전환. CTA는 유지하되 편집 몰입을 방해하지 않는다.

v1 문서는 "다운로드 전환 퍼널"을 1순위로 잡았다. 이 문서에서 뒤집었고, 그 결과 정렬 도구와 도형이 1차 범위로 들어왔다.

## 현재 코드 기준선 (2026-07-30 확인)

- `/playground` 페이지는 존재하지 않는다. v1 문서가 언급한 `PlaygroundCanvas` 플레이스홀더도 없다. 신규 생성이다.
- `resolveFontPreview`는 구현돼 있다(`apps/web/lib/fontPreview.ts`). self-host는 `next/font` 패밀리, Tier A는 Google CSS2 URL, 나머지는 Pretendard 폴백을 반환한다. v1의 Slice 0 선행 의존은 해소됐다.
- `LazyFontPreview`(`apps/web/components/LazyFontPreview.tsx`)가 IntersectionObserver 기반 스타일시트 지연 주입과 중복 방지를 이미 한다. 폰트 패널에서 재사용한다.
- 폰트 데이터: Tier A 140종(고딕 98, 명조 20, 장식 14, 손글씨 8, 빈 값 없음), Tier B 1,154종. Tier B는 웹폰트 파일이 없어 대상 외.
- 빌드는 `output: "export"` 정적 내보내기. 서버 라우트 없음. 서버 단계 searchParams 접근은 알려진 빌드 함정이므로 클라이언트 훅으로만 읽는다.
- 헤더 메뉴는 폰트/트렌드/컬렉션/등록 4개(`apps/web/components/Header.tsx`).

## 엔진: Fabric.js 7

- 2026-07-30 npm 확인: fabric 7.4.0, MIT, 타입 정의 내장.
- 채택 이유: 캔버스 위 텍스트 인라인 편집이 내장된 유일한 후보. 이 편집기의 핵심 동작이다.
- 배제: react-konva 19.2.5(MIT)는 인라인 텍스트 편집을 직접 구현해야 해 공수 1.5~2배. 직접 구현은 조작 손잡이와 내보내기까지 수작업이라 범위 밖.
- v1 문서는 v6 기준이었다. 메이저 두 단계 차이가 있으므로 문서의 코드 수준 세부는 그대로 믿지 않는다.
- `/playground` 진입 시에만 동적 로드해 타 페이지 번들에 영향을 주지 않는다.

## 환각 방지 규칙 (필수)

Fabric 7은 학습 데이터에 v6 이하 자료가 압도적으로 많아 API 환각 위험이 높다. 구현 시 다음을 지킨다.

- Fabric API를 쓰기 전 context7 MCP로 해당 API를 조회한다. 라이브러리 ID는 `/websites/fabricjs`(fabricjs.com API 문서, 2026-07-30 조회 확인).
- 조회 없이 기억에 의존해 메서드명이나 시그니처를 쓰지 않는다. 조회 결과에 없으면 구현하지 말고 보고한다.
- 확인 완료 예시: `initDimensions()`는 존재한다(`src/shapes/Text/Text.ts:475`, 텍스트 width/height 재계산). `loadFromJSON`은 Promise를 반환한다.
- 첫 슬라이스에서 v6 대비 변경점(캔버스 생성, dispose, 이벤트명, toDataURL 옵션, 그룹/다중선택 API)을 한 번에 조회해 정리하고, 그 결과를 구현 계획에 기록한다.

## 범위

### 1차 포함

- 텍스트: 제목/부제/본문 프리셋 3종으로 추가, 더블클릭 인라인 편집.
- 폰트 적용: Tier A 140종. 검색, 분류 칩(전체/고딕/명조/손글씨/장식), 미리보기.
- 도형: 사각형, 선 2종(채우기색, 테두리, 불투명도).
- 정렬 도구: 다중 선택(드래그 박스, Shift 클릭), 맞춤(좌/중앙/우/상/중간/하), 간격 균등, 앞뒤 순서, 스냅 안내선, 방향키 미세 이동, 복제.
- 되돌리기/다시하기.
- 캔버스: 프리셋 3종(1280x720, 1080x1080, 2560x1440) + 자유 크기(최대 4096), 줌 25~200%, 화면 맞춤.
- 내보내기: PNG.
- 모바일(900px 미만): 하단 시트 축소 경험.
- 계측 4종.

### 1차 제외 (2차 이슈로 분리)

이미지 업로드, PDF 내보내기, 저장/불러오기, 레이어 패널, 템플릿, 폰트 조합 추천, 원/다각형 등 추가 도형, italic 축, 계정/협업.

## 화면

### 데스크톱 (900px 이상)

상단 툴바 + 좌측 폰트 패널 + 중앙 캔버스 + 우측 속성 패널의 3분할.

- 툴바: 제목/부제/본문, 사각형/선, 맞춤/간격/앞뒤, 되돌리기/다시, 캔버스 프리셋, 줌, PNG 내보내기.
- 좌측 패널: 최상단에 "이 작업에 쓴 폰트" 목록 고정(각 항목에서 폰트 상세로 이동, CTA 자리). 아래에 검색, 분류 칩, 폰트 목록.
- 우측 패널: 선택 객체 속성. 텍스트는 크기, 굵기(해당 폰트의 availableWeights만), 색, 자간, 행간, 정렬, 불투명도. 도형은 채우기색, 테두리, 불투명도.

### 모바일 (900px 미만)

캔버스 아래 하단 시트에 폰트/속성 탭.

동작 범위를 명시한다.

| 모바일에서 되는 것 | 모바일에서 안 되는 것 |
|---|---|
| 텍스트 추가(프리셋 3종), 더블탭 내용 편집 | 크기 조절 손잡이 드래그, 회전 |
| 객체 선택과 드래그 이동 | 다중 선택(드래그 박스), 간격 균등 |
| 폰트 적용, 속성 편집, 삭제 | 스냅 안내선(표시는 하되 흡착 판정은 데스크톱만) |
| 되돌리기, PNG 내보내기 | 자유 크기 캔버스 입력 |

크기 조절은 손잡이 대신 속성 패널의 크기 값 입력으로 대신한다.

캔버스 영역은 터치 조작이 페이지 스크롤이나 확대로 새어나가지 않도록 브라우저 기본 터치 동작을 끈다(`touch-action: none` 계열). 이 처리를 빼면 객체를 끌 때 페이지가 함께 움직인다.

기준 폭 900px은 프로젝트가 이미 쓰는 값이다(신규 브레이크포인트를 만들지 않는다).

### 첫 진입과 진입 경로

- 첫 화면은 빈 캔버스. 텍스트는 툴바 버튼으로만 생성한다(캔버스 더블클릭 생성 없음).
- 선택된 객체가 없을 때 폰트를 클릭하면 "다음에 추가할 텍스트의 기본 폰트"로 기억하고 목록에 선택 표시를 남긴다.
- 헤더 메뉴에 플레이그라운드를 추가한다.
- 폰트 상세 페이지에 "이 폰트로 만들어보기" 버튼을 둔다. `?font=<slug>`로 전달하고 편집기는 클라이언트에서 읽어 기본 폰트로 적용한다.
- 이 버튼은 웹 렌더링 가능한 폰트(self-host 또는 Tier A)에서만 노출한다. Tier B 1,154종은 웹폰트 파일이 없어 편집기에서 적용할 수 없으므로 버튼을 숨긴다. 전체 폰트의 89%가 Tier B이므로, 조건 없이 노출하면 대다수 상세 페이지에서 동작하지 않는 버튼이 보인다.
- `?font=` 값이 없거나 편집기 폰트 목록에 없는 값이면 조용히 기본 폰트로 시작한다.

## 아키텍처

- 전 기능이 브라우저에서 동작한다. 서버 라우트, DB 스키마 변경 없음.
- 폰트 목록은 빌드 시점에 서버 컴포넌트가 읽어 클라이언트 편집기에 props로 내려준다. 런타임 추가 요청 없음.
- 폰트 식별자는 `slug` 하나로 통일한다. 캔버스 객체에 붙는 값, 계측 파라미터, CTA 링크, 스냅샷 복원 키가 모두 `slug`다. 표시명-CSS 패밀리-스타일시트 URL-지원 weight는 `slug`로 조회한다. `fontKey`와 `fontFamily`는 `resolveFontPreview` 내부 구현 값이며 편집기 상태에 저장하지 않는다.
- 편집기가 쓰는 폰트 항목 형태: `slug`, 표시명(한글/영문), `sourceTier`, `category`, `availableWeights`, `fontFamily`, `stylesheetUrl`(self-host는 없음), 상세 경로.
- 편집 상태의 단일 원본은 Fabric 캔버스 객체 트리다. React는 상태를 복제하지 않고 Fabric 이벤트를 구독해 패널 표시만 갱신한다.
- `CanvasStage`는 마운트 시 초기화하고 언마운트 시 반드시 dispose 한다. React 개발 모드의 이중 마운트에서 캔버스와 이벤트 핸들러가 중복 생성되면 안 된다.
- 편집 내용이 있을 때 페이지 이탈 시 브라우저 경고 1회. 사이트 내 이동은 App Router에 라우트 전환을 가로채는 공식 수단이 없으므로, 편집기 화면 안의 이동 링크(헤더, 폰트 상세 CTA)를 감싸 클릭 시 확인 창을 띄우는 방식으로 한정한다. 브라우저 뒤로가기까지 막지는 않는다.

### 컴포넌트 밖 순수 로직 (단위 테스트 대상)

- 폰트 적용 정책: 스타일시트 주입 중복 방지, 로딩 대기, 세대 토큰으로 마지막 요청만 반영.

- 스냅 판정: 후보 안내선 산출과 흡착 여부.
- 프리셋 변경 시 비례 재배치 계산.
- 내보내기 배율 계산.

## 데이터 흐름

### 폰트 적용

1. self-host 8종은 이미 번들에 있어 즉시 적용한다.
2. 그 외 Tier A는 `resolveFontPreview`가 주는 CSS2 URL을 주입한다(같은 URL은 1회).
3. `document.fonts.load`로 실제 로딩 완료를 기다린다(타임아웃 5초).
4. 반영 직전에 대상 객체가 아직 캔버스에 있는지 확인한다. 5초를 기다리는 동안 사용자가 그 객체를 지웠거나 되돌리기로 사라졌을 수 있다. 없으면 조용히 버린다.
5. 대상 객체 fontFamily 반영 후 텍스트 치수를 재계산하고 다시 렌더한다. 기다리지 않고 적용하면 글자 폭이 이전 폰트 기준으로 남아 배치가 틀어진다.
6. 연속 클릭 대비로 요청 세대 토큰을 두고 마지막 선택만 반영한다. 세대 토큰은 객체 식별자와 짝으로 관리해, 다른 객체를 향한 늦은 응답이 엉뚱한 객체에 적용되지 않게 한다.
7. 로딩 전과 실패 시에는 Pretendard 폴백을 유지한다.

### 굵기 대체 규칙

텍스트 프리셋은 제목 700, 부제 500, 본문 400을 요구하지만 모든 폰트가 그 weight를 갖지는 않는다(장식과 손글씨 계열은 400 하나뿐인 경우가 많다). 요청한 weight가 `availableWeights`에 없으면 가장 가까운 값으로 대체하고, 같은 거리면 굵은 쪽을 택한다. 속성 패널은 대체된 실제 값을 표시한다.

### 내보내기 직전 검사

PNG를 만들기 전에 이 작업에 쓰인 모든 폰트의 로딩이 끝났는지 확인한다. 확인 없이 내보내면 화면에는 적용돼 보이는데 저장된 이미지는 폴백 폰트로 나오는 불일치가 생긴다. 아직 로딩 중이면 완료를 기다렸다가 진행하고, 실패한 폰트가 있으면 "일부 폰트가 기본 글꼴로 저장됩니다"를 알린 뒤 사용자가 계속할지 정하게 한다.

### 적용 대상

선택된 객체가 텍스트면 그 객체에, 다중 선택이면 선택된 텍스트 전부에, 선택이 없으면 다음 생성 텍스트의 기본값에 적용한다.

### 프리셋 변경

가로세로 비율에 맞춰 객체 위치와 크기를 비례 재배치해 캔버스 밖으로 나가지 않게 한다. 기준점은 각 객체의 중심이다. 가로와 세로 배율 중 작은 값을 크기에 적용하고(가로세로 비율 유지), 중심 좌표는 캔버스 대비 상대 위치를 그대로 옮긴다. 비율 차이가 큰 전환(16:9 to 1:1)에서는 여백이 생길 수 있다.

## 기본값 (구현 중 조정 가능)

| 항목 | 값 |

## 되돌리기 (스냅샷)

**시점**: 객체 추가, 삭제, 이동/크기변경 종료, 속성 변경 확정, 폰트 적용, 프리셋 변경. 드래그 도중에는 찍지 않는다.

**직렬화**: 캔버스 직렬화는 라이브러리가 아는 표준 속성만 담고 커스텀 속성은 기본적으로 빠진다. 객체에 붙인 `slug`(적용 폰트)와 객체 식별자를 직렬화 대상에 명시적으로 포함시킨다. 빠뜨리면 되돌리기 한 번에 사용 중 폰트 목록과 CTA가 어긋난다.

**복원 잠금**: 스냅샷 복원은 비동기다(Fabric의 `loadFromJSON`은 Promise 반환, context7 확인). 복원이 진행 중이면 다음 되돌리기/다시하기 요청을 받지 않는다. 잠그지 않으면 단축키 연타 시 캔버스 내용과 스택 위치가 어긋난다.

**단축키 컨텍스트**: 되돌리기, 삭제, 복제, 방향키 이동은 캔버스에 포커스가 있을 때만 동작한다. 캔버스 위 텍스트를 인라인 편집 중이거나 속성 패널 입력 요소에 포커스가 있으면 전역 단축키를 무시한다. 이 분리가 없으면 글자를 지우려고 Backspace를 눌렀을 때 텍스트 객체 자체가 삭제된다.

## 라이선스 고지

무료 폰트라도 이미지 제작과 임베드 허용 범위가 폰트마다 다르다. 내보내기 시점에 이번 작업에 쓴 폰트 목록과 각 상세 링크, 그리고 "사용 전 라이선스 조건을 확인하세요" 한 줄을 표시한다. 폰트 목록 항목에 상업 사용 가능 여부 배지는 붙이지 않는다(라이선스 감사가 진행 중이라 오정보 위험).

## 에러 처리

| 상황 | 처리 |
|---|---|
| 폰트 로딩 실패/타임아웃 | 폴백 유지 + 안내. 편집은 계속 가능 |
| 내보내기 실패 | 사유 안내 + 재시도. 크기 초과는 자동 축소 후 축소 사실 표시 |
| 잘못된 `?font=` 값 | 조용히 기본 폰트로 시작 |
| 편집 중 이탈 | 브라우저 경고 1회 |
| 캔버스 자유 크기 입력 | 200~4096 범위 검증, 위반 시 거부 + 사유 안내. 소수-빈값-문자 입력도 거부 |
| 내보내기 시 폰트 미로딩 | 완료 대기 후 진행. 실패한 폰트가 있으면 기본 글꼴로 저장됨을 알리고 사용자가 계속 여부 결정 |

## 계측 (GA4)

- `playground_text_added` (프리셋 종류)
- `playground_font_applied` (폰트 slug, 그 시점까지 적용한 서로 다른 폰트 수)
- `playground_export_png` (캔버스 프리셋, 객체 수, 사용 폰트 수)
- `playground_font_cta_clicked` (폰트 slug, 진입 위치: 사용 중 폰트 목록 또는 내보내기 고지)

같은 폰트를 연속으로 다시 클릭했을 때는 이벤트를 보내지 않는다(실제로 바뀐 경우만 집계).

앞의 셋으로 실험 행동을, 마지막 하나로 전환을 본다. 기존 `font_download_clicked`와 이어 퍼널을 완성한다.

## 테스트

- 단위(vitest): 폰트 적용 정책(세대 토큰-타임아웃), 되돌리기 스택, 정렬 계산, 스냅 판정, 비례 재배치, 내보내기 배율. Fabric에 직접 의존하지 않는 순수 함수만 대상으로 하고 컴포넌트는 mock.
- 브라우저(Playwright) 3개: (1) 텍스트 추가 to 폰트 적용 to PNG 다운로드, (2) 두 객체 선택 to 왼쪽 맞춤 to 위치 확인, (3) 폰트 적용 to 사용 중 폰트에서 상세 이동.
- db를 import 하는 컴포넌트 테스트는 db 모듈 mock 필수(기존 관례).
- 배포 후 스모크: 운영에서 Google Fonts 로드, PNG 다운로드, CTA 이동 확인.

## 위험

- 스냅과 정렬은 시각적 기능이라 자동 테스트로 전부 검증되지 않는다. 수동 확인 항목을 구현 계획에 명시한다.
- Fabric 7 자료 부족으로 구현 중 API 차이에 막힐 수 있다. 환각 방지 규칙으로 완화하되, 조회해도 답이 없으면 진행하지 말고 보고한다.
- 모바일 터치 동작은 기기 편차가 있다. 지원 범위를 이동과 선택으로 좁혀 위험을 줄였다.
- 범위가 v1 대비 약 2배다(슬라이스 5~6개에서 9~10개). 일정 재산정이 필요하다.
- 접근성: 캔버스 편집은 스크린리더로 조작하기 어렵다. 1차에서는 키보드만으로 텍스트 추가와 폰트 적용이 가능한지까지만 확인하고, 캔버스 영역에 대체 설명을 제공한다. 완전한 키보드 편집은 비범위다.

## 공수

세로 슬라이스 9~10개. 큰 덩어리는 캔버스 기반(엔진 연결-정리-줌), 텍스트와 폰트 적용, 정렬 도구와 스냅, 도형, 내보내기와 고지, 모바일 시트, 계측이다.
