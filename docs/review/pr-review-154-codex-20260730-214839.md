### Critical 이슈 - Must-fix (머지 차단)

#### 1. 증거 역할과 허용 필드가 교차 오염됩니다

- 제안 수정: 필드와 역할의 정확한 허용 조합을 정의해야 합니다. `official_url`은 `noonnu-official-url-anchor`만, 새 마커는 `official_url`·`license_source_url`만 허용하십시오. Python 검증도 `field_name`을 받도록 바꾸고 동일한 규칙을 사용해야 합니다. 이미 0027이 운영에 적용됐으므로 0027을 수정하는 대신 0028 보정 마이그레이션을 추가해야 합니다.

  - URL의 페이지 ID와 `provider_record_id` 일치

### 긍정적 관찰

- `--store-findings`를 dev로 제한한 점은 운영 오적재 방지에 효과적입니다.
- `auto_applicable=true`를 기본 조회 조건으로 추가해 기존의 370건 과승인 문제를 막았습니다.
- `document_kind="metadata"` 회귀 테스트는 실제 DB 제약 위반을 정확히 고정합니다.
- 리다이렉트마다 허용 호스트를 검사해 서버 측 요청 위조(SSRF) 위험을 줄였습니다.
- SQL의 서비스 역할 확인, 빈 `search_path`, manifest 해시, 정확한 JSON 키 검사, `updated_at` 및 before 값 검사는 좋은 방어 장치입니다.
- 변환 로직을 `noonnu_url_ingest.py`의 순수 함수로 분리하고 저장 예외를 삼키지 않은 점은 좋습니다.
- 역방향 manifest와 운영 함수 백업을 준비한 점은 사후 복구 측면에서 적절합니다.
