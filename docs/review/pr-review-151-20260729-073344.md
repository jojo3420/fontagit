- 제안 수정: 기존 호출처의 저장·비교 동작을 확인하고, 스냅샷 스키마 변경임을 PR 설명에 명시하세요.

### 긍정적 관찰

- `noonnu_url_audit.py`를 순수 판정 모듈로 분리한 것은 단일 책임 원칙에 맞습니다.
- DB 요청은 `select`만 사용하므로 이 PR 자체에는 DB 쓰기 경로가 없습니다.
- 거대한 `in-list` 쿼리를 피하고 `range()` 페이지네이션을 도입한 방향은 맞습니다.
- `retryable_error`를 추가하고 동일 `font_id`의 마지막 기록을 채택한 것은 #142 재발 방지의 올바른 출발점입니다.
- `fetch_scan_html()`이 `HTTPStatusError`를 그대로 전달하므로 429/403 백오프는 실제 실행 경로에서 동작합니다. 관련 통합 테스트도 존재합니다.
- User-Agent, 1.5초 이상 지연, 지터, 동시 요청 금지는 외부 사이트 부하를 줄이는 좋은 기본값입니다.
- 고정 쿼리 필터를 사용하고 시크릿을 로그에 출력하지 않아 SQL 인젝션이나 시크릿 노출 문제는 보이지 않습니다.

### C3이 최우선인 이유

이 도구는 오염을 "찾아내는" 것이 존재 이유다. 그런데 상세 영역 안에 눈누 SNS 링크가 있는 페이지에서는
재추출 값 == DB 값이 되어 `match / keep`으로 판정된다. 찾아야 할 대상이 정상으로 분류된다.

PR #149 실증(font_page/600)에서는 링크가 상세 밖이라 이 경로를 타지 않았으나, 1,110개 전체가 그렇다는
근거는 없다. 판정 순서 결함 자체는 데이터와 무관하게 성립한다.

### 설계 문서 정정 필요

`docs/superpowers/specs/2026-07-28-noonnu-official-url-audit-design.md`에 "눈누 수집기는 이미 정직한 봇
UA와 robots.txt 준수, 요청 간 지연을 갖추고 있어 변경하지 않는다"고 적었으나, 이는 `collect_noonnu_seeds`
경로에만 해당한다. 새로 만든 `noonnu_url_scan.py`는 robots.txt를 확인하지 않는다. 문서를 고쳐야 한다.
