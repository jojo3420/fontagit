### 구체적 피드백

1. **[Blocker] `license_source_url` 오염 정정 계획 누락**
   - 배경에서 172종의 오염 현황으로 `official_url = license_source_url = 눈누 공식 인스타그램`이 명시되었습니다.
   - 하지만 설계 및 정정 적용 단계에서는 `official_url`만 언급하고 있습니다. 라이선스 판정의 핵심 근거가 되는 `license_source_url` 또한 함께 정정되어야 하므로, 이 필드 역시 `0026` 마이그레이션의 `v_allowed` 추가 대상 및 정정 manifest 대상에 포함시키는 설계가 보완되어야 합니다.

2. **[Blocker] `license_verified` 강등(false)을 위한 manifest 권한 확인**
   - 새 제작사 근거 URL을 찾지 못할 경우 `license_verified`를 `false`로 내리겠다고 명시되어 있습니다.
   - 이 필드가 manifest RPC의 변경 허용 목록(`v_allowed`)에 이미 존재하지 않는다면, `0026` 마이그레이션 적용 시 `official_url`과 함께 허용 목록에 추가하는 설계가 반영되어야 합니다.

3. **`audit_http.py` (curl 기반)의 robots.txt 및 Rate Limit 구현 방식 모호성**
   - `#141 fetcher` 설명에서 curl 기반 fetcher인 `audit_http.py`에 robots.txt 확인과 요청 간격 제한을 넣는다고 설계되어 있습니다.
   - Python의 정식 수집 봇 계열이 아닌 curl subprocess 환경에서 robots.txt를 어떻게 파싱하고 호스트별 딜레이를 제어할 것인지에 대한 구체적인 구현 방식이 보완되면 좋겠습니다.

4. **대조 스캐너의 재개(Resume) 로직 상세 설계 누락**
   - 리스크 섹션에는 "중단 시 재개할 수 있도록 진행 상태를 파일로 남긴다"고 언급되어 있으나, 컴포넌트 1(대조 스캐너) 설계에서는 상태 파일 포맷이나 CLI 레벨에서의 재개(예: `--resume` 플래그 등) 구동 방식이 구체화되어 있지 않습니다.

### 개선 제안

1. **(최우선) WAF 차단 회피를 위한 무작위 지터(Jitter) 도입**
   - 1,110회 요청을 1초 고정 지연으로 연속해서 보낼 경우 눈누 측 WAF(예: Cloudflare, AWS WAF 등)에서 패턴으로 감지되어 IP 차단(429 Too Many Requests 또는 403 Forbidden)을 당할 리스크가 큽니다.
   - 1.0초 ~ 2.5초 사이의 무작위 지터를 섞고, WAF 차단 발생 시 즉시 대기 시간을 강제로 늘리거나 실행을 안전하게 중단(fail-fast)하는 백오프(Backoff) 로직을 추가할 것을 권장합니다.

2. **(우선) `no_container`에 대한 폴백 수집 전략 마련**
   - PR #149에서 수정된 추출기가 fail-closed 방식으로 동작하므로, 눈누의 일부 비정형 폰트 상세 페이지에서 `no_container` 판정이 예상보다 대량 발생할 수 있습니다.
   - 전수 검증 리포트에서 `no_container` 비율이 임계치(예: 전체의 5%)를 초과할 경우, 기존의 느슨했던 selector나 차선책 selector로 폴백하여 데이터를 수집하는 2단계 스캔 로직을 구현하면 데이터 유실을 줄일 수 있습니다.
