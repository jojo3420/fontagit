### 구체적 피드백

1. **[Blocker] 지원 폰트 범위와 진입 경로가 충돌합니다.**  
   편집기는 Tier A 140종만 지원하지만 “폰트 상세의 만들어보기 버튼”이 어느 폰트에 노출되는지 없습니다. Tier B 폰트가 들어오면 Pretendard로 조용히 대체될 수 있습니다. 버튼은 지원 폰트에만 노출하고, 알 수 없는 `?font=` 값은 명확히 거부해야 합니다.

2. **[Blocker] 폰트 굵기 변경 시 실제 폰트 파일을 불러오는 규칙이 없습니다.**  
   폰트 선택 때만 로딩하면 굵기를 바꿨을 때 브라우저가 가짜 굵기나 대체 폰트를 사용할 수 있습니다. `availableWeights`에 있는 값만 보여주고, 굵기 변경과 PNG 출력 전에 해당 굵기의 로딩 완료를 확인해야 합니다.

3. **[Blocker] 되돌리기 대상이 불완전합니다.**  
   현재 규칙에는 캔버스 크기 변경, 글자 내용 편집, 폰트 적용, 복제, 앞뒤 순서 변경이 빠져 있습니다. 최초 상태 저장, 되돌린 뒤 새 편집 시 다시하기 기록 삭제, JSON 복원 중 이벤트 기록 금지도 정해야 합니다.

4. **[Blocker] 비동기 폰트 로딩과 되돌리기가 충돌할 수 있습니다.**  
   폰트 로딩 중 객체를 삭제하거나 되돌리면 늦게 끝난 요청이 과거 상태를 다시 변경할 수 있습니다. 요청 순번뿐 아니라 객체 ID와 현재 문서 버전을 함께 확인해야 합니다.

5. **[Blocker] 캔버스 크기 변경 계산이 모호합니다.**  
   위치와 객체 배율, `fontSize`를 모두 곱하면 글자가 이중으로 축소·확대될 수 있습니다. 배율은 한 번만 적용하고, 남는 공간은 중앙 정렬할지 좌측 상단에 둘지 명시해야 합니다.

6. **[Blocker] PNG 픽셀 제한과 허용 크기가 충돌합니다.**  
   `4096×4096`은 약 1,678만 픽셀로 1,600만 상한을 이미 넘습니다. 출력 배수를 1보다 작게 허용할지, 입력 크기를 제한할지와 정확한 계산식을 정해야 합니다.

7. PNG 출력 규칙에 배경색, 줌 제외, 선택 테두리 제외, 최종 픽셀 크기가 없습니다. 출력 중 폰트 로딩을 다시 확인하고, 실패·연속 클릭·메모리 부족 처리도 필요합니다.

8. “Fabric 캔버스가 유일한 상태 정본”은 표현을 좁혀야 합니다. 캔버스는 문서 내용의 정본일 수 있지만 검색어, 기본 폰트, 줌, 로딩 상태, 변경 여부, 대화상자 상태는 별도 편집기 상태입니다.

9. `fontLoading.ts`는 스타일시트와 브라우저 폰트 API를 조작하므로 순수 함수가 아닙니다. URL·배수 계산 같은 순수 로직과 실제 브라우저 조작 코드를 분리해야 테스트 설명과 일치합니다.

10. 상세 페이지 이동과 이탈 경고가 서로 방해합니다. 전환 링크를 누를 때마다 작업 손실 경고가 뜨면 핵심 전환 흐름이 나빠집니다. 상세 및 라이선스 링크는 새 탭으로 여는 편이 안전합니다.

11. 폰트 메타데이터 구조가 필요합니다. 최소한 `slug`, 표시명, CSS용 이름, 분류, 사용 가능한 굵기, 라이선스명·URL, 상세 URL, 지원 여부를 명시해야 합니다. URL 파라미터 값은 이 목록을 기준으로 검증해야 합니다.

12. 사용 가능한 폰트라는 이유만으로 PNG 이용 조건까지 충족하는 것은 아닙니다. 출시 전에 웹폰트 사용과 이미지 제작이 허용되는지 확인하고, 실제 적용된 폰트만 중복 없이 고지해야 합니다.

13. 기본 동작이 부족합니다. 최초 기본 폰트, 새 텍스트의 내용·위치·크기, 빈 문자열 처리, 여러 객체 선택 시 미리보기 문구, 속성별 단위와 범위, 캔버스 최소 크기를 정해야 합니다.

14. 객체를 캔버스 밖으로 완전히 이동했을 때 복구 방법이 없습니다. 이동을 제한하거나 “가운데로 가져오기” 기능이 필요합니다. 안내 문구는 PNG와 되돌리기에 포함되지 않는 HTML 안내층으로 명시하는 것이 안전합니다.

15. 단축키는 텍스트 편집창이나 숫자 입력창에 커서가 있을 때 동작하면 안 됩니다. Windows용 `Ctrl+Y`, 글자 편집 중 `Cmd/Ctrl+Z`, Delete 키 처리 기준도 필요합니다.

16. 좁은 화면에서 Fabric을 실제로 불러오지 않는지, 화면 폭이 바뀌었다가 돌아왔을 때 작업이 유지되는지 불명확합니다. 단순히 컴포넌트를 제거하면 작성 중인 내용이 사라질 수 있습니다.

17. 측정 이벤트의 성공 기준이 없습니다. 폰트 적용은 로딩 성공 후, PNG 출력은 파일 생성 성공 후 기록해야 합니다. 사용자가 입력한 문구는 분석 데이터로 보내지 않는다는 규칙도 필요합니다.

18. 검증 계획에 자유 크기 유효성, 되돌리기 복원, 출력 PNG 크기 확인이 빠졌습니다. Fabric 모의 객체만으로는 실제 한글 입력과 폰트 출력 문제를 잡기 어렵습니다.

19. 이전 설계와 이슈 요구사항의 변경표가 없습니다. 어떤 요구가 유지·변경·삭제됐는지 표로 남겨야 문서 간 일관성을 확인할 수 있습니다.

20. Fabric 검증은 단순 API 확인보다 작은 사전 실험이 필요합니다. 한글 조합 입력, 사용자 정의 속성의 JSON 복원, React 중복 초기화, 실제 PNG 출력까지 통과해야 본 구현에 들어갈 수 있습니다.

### 구체적 피드백

1. **[Blocker] Next.js 정적 내보내기(`output: "export"`) 시 `useSearchParams` `<Suspense>` 감싸기 필수**
   - 폰트 상세에서 `?font=슬러그` 파라미터를 읽기 위해 Next.js App Router의 `useSearchParams()`를 클라이언트 컴포넌트에서 호출할 때, `<Suspense>` 경계로 감싸지 않으면 `next build` static export 단계에서 빌드 에러(`Missing Suspense boundary with useSearchParams`)가 발생합니다.
   - `app/playground/page.tsx` 또는 `PlaygroundEditor.tsx` 내에서 `useSearchParams`를 사용하는 컴포넌트 상위에 `<Suspense>` 적용 구조가 설계 명세에 포함되어야 합니다.

2. **[Blocker] 폰트 적용 시 CSS 주소 주입 외 `document.fonts.load()` 동기화 필수**
   - 웹폰트 `<link>`나 `<style>` 주입만으로는 Fabric.js 캔버스가 해당 폰트의 글리프 메트릭(글자 너비/높이)을 즉시 계산하지 못하고 기본 폰트로 렌더링되거나 글자 상자가 어긋납니다.
   - `fontLoading.ts`에서 스타일시트 주입 후 `await document.fonts.load('16px "' + fontFamily + '"')` 또는 `document.fonts.ready`를 기다린 다음 `object.set('fontFamily', fontFamily)` 및 `canvas.requestRenderAll()`을 호출하도록 동작 규칙에 명시해야 합니다.

3. **[High] 텍스트 인라인 편집 상태(`isEditing`)와 키보드 단축키(Undo/Delete) 충돌 예외 처리**
   - 캔버스 객체 선택 상태에서의 `Delete`/`Backspace` 또는 `Cmd+Z`는 캔버스 객체 삭제 및 되돌리기로 동작해야 하지만, 사용자가 텍스트 글자를 직접 수정 중인 상태(Fabric `isEditing === true`)일 때는 브라우저 기본 텍스트 편집 동작이 수행되어야 합니다.
   - 글로벌 단축키 리스너(`useUndoStack` 등)에서 `activeObject.isEditing` 상태를 감지하여 캔버스 단축키 동작을 차단하는 로직이 필요합니다.

4. **[Medium] Fabric 텍스트 객체 타입 미정의 (`IText` vs `Textbox`)**
   - Fabric에는 자동 줄바꿈이 되지 않는 `IText`와 상자 너비에 따라 자동 줄바꿈되는 `Textbox`가 있습니다.
   - 포스터/카드뉴스 텍스트 편집기용으로는 너비 조절 시 자동으로 줄바꿈이 일어나는 `fabric.Textbox`가 적합하므로, 사용할 Fabric 객체 클래스를 명확히 규정할 필요가 있습니다.

5. **[Medium] 캔버스 크기 변경 시 객체 스케일링 방식 상세 정의**
   - 문서에 "가로세로 변화율 중 작은 쪽 기준으로 글자 크기를 함께 조정한다"고 기술되어 있습니다.
   - Fabric `Textbox`에서 `fontSize`를 변경하면 텍스트 줄바꿈 위치가 재계산되는 반면, `scaleX`/`scaleY`를 조정하면 전체 렌더링 형태가 비율 그대로 축소/확대됩니다.
   - `rescaleObjects.ts`에서 `fontSize`를 직접 변경할 것인지, `scaleX`/`scaleY` 및 `left`/`top` 좌표 비율만 조정할 것인지 계산 방식을 명시하는 것이 좋습니다.

6. **[Low] `?font=슬러그` 진입 시 초기 진입 UX**
   - 첫 화면이 "빈 캔버스 + 안내 문구"로 명시되어 있으나, 폰트 상세 페이지에서 "이 폰트로 만들어보기"를 눌러 진입한 경우 해당 폰트가 적용된 샘플 텍스트가 캔버스 중앙에 자동 추가되면 사용자 경험이 훨씬 매끄럽습니다.

   - 캔버스 선택 객체 삭제를 위한 `Delete` / `Backspace` 키보드 이벤트 명세 추가.
   - `?font=슬러그` 쿼리가 존재할 경우 기본 텍스트 1개 자동 생성 흐름 추가.

3. **우선순위 3 (기술 리스크 대비)**
   - Fabric v7 API 변경점(v6 대비 `toObject()`, `loadFromJSON()` 비동기(Promise) 전환, `fabric.Canvas` 생성 방식 등) 사전 점검 항목을 기술 위험 섹션에 구체화.

### 모델 합의도

- 합의 지적: 2건 (크기 변경 배율 이중 적용, 단축키 차단) — 둘 다 실재 확인
- Codex 단독: 20건 (동의 14 / 부분 동의 5 / 비동의 1)
- agy 단독: 6건 (동의 2 / 부분 동의 2 / 비동의 1 / 나머지는 중복)
- 두 모델 모두 놓쳐 Claude가 발견: 2건 (26, 27번)

### 동의하는 핵심 피드백 Top 3

1. **4096 x 4096 = 16,777,216 픽셀**로 문서가 정한 1600만 상한을 자체 위반한다. 숫자 하나가 두 규칙을 동시에 무효화하므로 착수 전 반드시 정정해야 한다.
2. **`useSearchParams` Suspense 경계 누락.** 이 프로젝트는 이미 두 페이지에서 Suspense로 감싸고 있으며(`apps/web/app/fonts/page.tsx:17`, `apps/web/app/search/page.tsx:136`), 정적 내보내기에서 빠뜨리면 빌드가 깨진다. 14줄이 "클라이언트에서 읽는다"까지만 말하고 멈춘 것이 실제 위험이다.
3. **`lib/playground/`를 "전부 순수 함수"로 규정한 것과 `fontLoading.ts`의 역할이 충돌한다.** 테스트 전략(90줄)이 이 전제 위에 서 있어서, 전제가 틀리면 검증 계획 전체가 흔들린다.

### 동의하지 않는 피드백

- **Codex 18(검증 계획 누락)**: 90줄이 이미 되돌리기 순서와 내보내기 배수 검증을 명시하고, 자유 크기 검증은 65줄 `canvasPresets.ts`의 책임으로 배정돼 있다. "빠졌다"는 사실과 다르다. 단 "Fabric 목만으로는 한글 입력을 못 잡는다"는 뒷부분은 타당해 Should로 남긴다.
- **agy 일관성 "양호" 평가**: 66줄 vs 72줄, 90줄 vs 64-69줄 두 곳에서 문서가 스스로 모순된다. Codex의 "미흡" 평가가 원문에 더 부합한다.

### 두 모델이 놓친 관점

- 순수 함수 개수 불일치(26번) — 테스트 대상 목록에서 `canvasPresets`가 누락됐다.
- 폰트 주입 경로 이원화(27번) — 목록 미리보기와 캔버스가 서로 다른 코드로 같은 웹폰트를 주입하면 중복 요청과 캐시 불일치가 생긴다.

## 3. 통합 권고사항 (합집합)

### 즉시 반영 (Must) — 착수 전 문서 수정

1. **자유 크기 상한 재정의** (Codex): 4096 x 4096이 1600만 픽셀 상한을 넘는다. 한 변 상한을 낮추거나(예: 3900), 총 픽셀 상한을 별도 검증으로 분리하고 계산식을 예시 숫자와 함께 적는다.
2. **Suspense 경계 명시** (agy): `?font=` 읽는 컴포넌트를 `<Suspense>`로 감싼다. 기존 두 페이지와 동일 패턴.
3. **Tier A 노출 조건 + `?font=` 검증 + 폰트 메타데이터 계약** (Codex): 지원 폰트에만 버튼을 노출하고, 목록에 없는 슬러그는 조용한 폴백 대신 명시적으로 거부한다. 검증 기준이 될 필드(슬러그, CSS 이름, 분류, 굵기 목록, 라이선스, 상세 URL)를 문서에 적는다.
4. **굵기별 웹폰트 로딩 규칙** (Codex): DB에 실제 굵기 목록 컬럼이 있는지 먼저 확인하고, 있는 값만 노출한다. 굵기 변경과 PNG 출력 직전에 해당 굵기 로딩 완료를 확인한다.
5. **스냅샷 대상 보강** (Codex): 캔버스 크기 변경, 글자 내용 편집, 폰트 적용, 복제, 순서 변경을 추가한다. 최초 상태 저장, 되돌린 뒤 새 편집 시 다시하기 기록 삭제, JSON 복원 중 이벤트 기록 금지도 함께 정한다.
6. **크기 변경 계산식 확정** (합의): 배율을 위치-`scale`-`fontSize` 중 어디에 한 번만 적용할지 정하고 예시 숫자로 검산한다. 남는 여백 처리(중앙 정렬/좌상단)도 명시한다.
7. **단축키 차단 조건** (합의): 텍스트 편집 중(`isEditing`)이거나 입력창에 초점이 있으면 캔버스 단축키를 막는다. Windows `Ctrl+Y`, Delete 키 기준도 정한다.
8. **`fontLoading.ts` 분리** (Codex + Claude): URL-순번 계산 같은 순수 로직과 스타일시트 주입을 분리하고, 72줄과 90줄의 "전부 순수 함수 / 4종" 표현을 실제 파일 5개와 맞춘다.
9. **늦은 폰트 응답 방어** (Codex): 순번 외에 대상 객체가 아직 캔버스에 있는지, 문서 버전이 같은지 확인한 뒤 적용한다.
10. **PNG 출력 규칙 보강** (Codex): 배경색, 줌 제외, 선택 테두리 제외, 최종 픽셀 크기를 정한다. 화면용과 별도의 출력용 캔버스를 쓰는 방식을 권고한다.

### 검토 후 반영 (Should)

- Fabric 텍스트 객체 타입(`IText`/`Textbox`) 확정 — 자동 줄바꿈 지원 여부가 갈린다 (agy)

- 캔버스 밖으로 나간 객체의 복구 수단(이동 제한 또는 "가운데로 가져오기") (Codex)
