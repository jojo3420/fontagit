### 구체적 피드백
1. **[차단] 1차 리뷰 반영 여부를 검증할 수 없습니다.**  
   이전 리뷰 결과와 항목별 반영표가 본문에 없습니다. 이번 메시지에는 Design만 있어 Plan과의 일관성도 확인할 수 없습니다. `리뷰 항목 → 반영 위치 → 미반영 사유` 표가 필요합니다.

2. **[차단] Google Fonts의 신뢰 등급이 모순됩니다.**  
   0장에서는 Google Fonts를 아카이브로 정의했지만, S1에서는 `METADATA.pb`를 공식 copyright 근거처럼 사용합니다. 아카이브 자료만으로 `foundry`를 자동 승인할지, 공식 권리사 자료로 추가 확인할지 명확히 정해야 합니다.

3. **[차단] `foundry`와 권리사의 의미가 불분명합니다.**  
   문서는 제작사를 권리사로 정의하지만 저장 필드는 `foundry`입니다. 기존 DB에서 `foundry`가 제작사·디자인사 중 무엇을 뜻하는지, 이번 변경이 기존 의미를 바꾸는지 명시해야 합니다.

4. **[차단] S1과 S2 실행 순서가 우선순위와 맞지 않습니다.**  
   Tier A 다운로드 주소는 S2의 눈누 결과를 활용한다고 했지만 실행 순서는 S1이 먼저입니다. S1의 아카이브 주소를 S2에서 공식 주소로 승격할지, S2를 먼저 실행할지 정해야 합니다.

5. **[차단] 자동 게이트와 `archive` 백필이 충돌합니다.**  
   자동 게이트는 공식 도메인 화이트리스트를 사용합니다. 그러나 Google Fonts·GitHub는 아카이브이므로 자동 적용되지 않을 가능성이 큽니다. `archive_allowlist`를 별도로 만들고 공식 출처로 오인하지 않도록 해야 합니다.

6. **[차단] 기존 값 덮어쓰기 규칙이 없습니다.**  
   이미 공식 URL이 있는데 아카이브 URL로 낮춰 버리는 상황을 막아야 합니다. 최소한 `official > public > archive > null` 우선순위와 “같거나 더 높은 등급만 갱신” 규칙이 필요합니다.

7. **[중요] `NHN Corporation → 네이버` 변환 근거가 부족합니다.**  
   회사명 변경이나 권리 승계 근거 없이 자동 정규화하면 법적 주체를 잘못 표시할 수 있습니다. 정규화 사전에 원본명, 표시명, 근거 URL, 적용 기간, 검수 상태를 함께 저장해야 합니다.

8. **[중요] S1 필드별 생성 근거가 빠졌습니다.**  
   `METADATA.pb`의 designer·copyright로 `foundry_url`, `download_url`, `license_source_url`까지 어떻게 만드는지 정의되지 않았습니다. 각 필드의 원본, 변환 규칙, 신뢰 등급을 표로 명시해야 합니다.

9. **[차단] KOGL 매핑이 기존 권한 모델 전체를 다루지 않습니다.**  
   현재 표에는 상업 이용과 수정 여부만 있습니다. 출처표시, 재배포, 폰트 자체 판매 금지를 DB의 어떤 필드에 저장할지 없습니다. 저장하지 못한다면 UI에서 정확한 조건을 보여줄 수 없습니다.

10. **[중요] KOGL 미검출 그룹의 승인 의미가 모호합니다.**  
    “최대 4그룹 + 미검출 승인”처럼 읽히지만 미검출은 허용값을 적용하면 안 됩니다. 미검출 그룹은 적용 승인이 아니라 보류 확인만 가능하다고 명시해야 합니다.

11. **[중요] KOGL 파서의 충돌 규칙이 없습니다.**  
    한 문서에서 여러 유형이 검출되거나, “제1유형이 아님” 같은 문장에 잘못 반응할 수 있습니다. 복수 검출, 부정문, HTML·공백 차이, 빈 값은 모두 `needs_review`로 보내야 합니다.

12. **[차단] 청크 재실행의 멱등성이 정의되지 않았습니다.**  
    “멱등 재실행”만으로는 부족합니다. 이미 반영된 항목을 성공으로 볼지, `before` 값 불일치를 오류로 볼지, 다른 작업이 값을 바꾼 경우 어떻게 보호할지 정해야 합니다.

13. **[차단] reverse manifest가 최신 변경을 덮어쓸 수 있습니다.**  
    적용 후 다른 사용자가 수정한 값을 reverse manifest가 과거 값으로 되돌릴 수 있습니다. 롤백 시 현재 값이 해당 manifest의 `after`와 일치할 때만 복구하는 조건이 필요합니다.

14. **[중요] 변경 수 검증 기준이 모호합니다.**  
    manifest 엔트리 수에는 이미 같은 값인 항목, `needs_review`, 부분 필드 적용이 섞일 수 있습니다. `계획·승인·변경·변경 없음·거절·실패`를 별도로 집계해야 합니다.

15. **[중요] 22종 재크롤의 실행 명세가 부족합니다.**  
    정확한 font ID·URL 목록, 최대 재시도 횟수, 대기 시간, 타임아웃, 리다이렉트, 삭제된 페이지 처리, 원본 응답 보관 위치가 필요합니다. 정확한 허용 목록으로 전량 크롤을 기술적으로 차단해야 합니다.

16. **[중요] 다운로드 페이지 URL 검증이 없습니다.**  
    파일 직링크 금지는 문자열만 보고 판단하기 어렵습니다. 최종 리다이렉트 주소, 응답 형식, HTTPS 여부, 허용 도메인, 추적 URL 제거 규칙을 정의해야 합니다.

17. **[보완] 견본 문구 선택 규칙이 충분히 고정되지 않았습니다.**  
    여러 태그가 있는 경우의 우선순위, 해시 알고리즘, 문구 배열 순서가 바뀔 때의 동작이 빠졌습니다. 문구별 고정 ID를 두고 `slug + 문구 그룹 ID`로 선택하는 편이 안전합니다.

18. **[보완] 화면 검증 기준이 모호합니다.**  
    “네이버 계열”, “실제 약관 페이지” 대신 기대 문자열과 URL을 정확히 지정해야 합니다. 제작사·다운로드·라이선스 원문이 각각 없는 경우의 화면 처리도 필요합니다.
